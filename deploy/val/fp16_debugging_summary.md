# FP16 精度调试总结

## 问题描述
FP16 模式下，SparseBox3DKeyPointsPlugin 的输出与 PyTorch 参考实现存在巨大误差（4.4e+11），导致成功率只有 3.3%-30%。

## 关键发现

### 1. FP32 vs FP16 引擎输出差异
- **FP32 引擎输出**: 正常（1.456089e+01）
- **FP16 引擎输出**: 异常（4.396042e+11）
- **差异**: 4.4e+11（系统性溢出）

### 2. FP32 模式完美
- **FP32 成功率**: 100% (60/60)
- **FP32 最大误差**: 3.81e-06
- **证明**: 插件实现逻辑正确

### 3. 输入数据检查
- **Anchor 数据**: 无 NaN/Inf，范围正常（center: [-53.669, 53.904]）
- **Instance 数据**: 无 NaN/Inf，范围正常（[-0.072044, 0.072043]）
- **FP16 转换**: 无 Inf/NaN 产生

### 4. 问题定位
- **问题位置**: Anchor 318, Keypoint 9, Axis 0
- **FP32 输出**: 1.456089e+01（正常）
- **FP16 输出**: 4.396042e+11（异常，可能是 Inf 传播）

## 已实施的优化措施

1. ✅ **混合精度累加**: 所有累加计算使用 FP32，使用 `fmaf` 进行融合乘加
2. ✅ **FP16 范围限制**: 在 `fromFloat<__half>` 中 clamp 到 [-65504, 65504]
3. ✅ **Sigmoid 数值稳定性**: 使用边界检查，clamp accum 到 [-88, 88]
4. ✅ **NaN/Inf 检查**: 所有中间值都进行 `isFinite()` 检查
5. ✅ **移除过度 clamp**: 只检查 NaN/Inf，不进行过度的数值范围限制

## 当前状态

- **FP16 成功率**: 3.3%-30%（不稳定）
- **失败案例误差**: 集中在 4.4e+11 左右（系统性溢出）
- **FP32 成功率**: 100%（证明实现正确）

## 可能的原因

1. **TensorRT 引擎优化问题**: TensorRT 在 FP16 模式下可能进行了某些优化，导致问题
2. **中间值溢出**: 虽然最终输出范围正常，但某个中间值可能超出了 FP16 范围
3. **Inf 传播**: 如果某个值转换为 FP16 时产生 Inf，这个 Inf 可能在后续计算中传播

## 下一步建议

1. **深入调试**: 使用 CUDA 调试工具（如 `cuda-gdb`）追踪具体的溢出点
2. **检查 TensorRT 引擎**: 验证引擎构建过程，考虑禁用某些优化选项
3. **对比 PyTorch 实现**: 检查 PyTorch 在 FP16 模式下的特殊处理
4. **考虑完全 FP32 模式**: 如果 FP16 精度问题无法解决，考虑在插件内部完全使用 FP32

## 结论

虽然已经进行了多项优化，但 FP16 模式的成功率仍然很低，距离 100% 的要求还有很大差距。问题可能是系统性的，需要更深入的调试和分析。
