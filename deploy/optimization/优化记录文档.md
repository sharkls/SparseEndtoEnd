# 优化记录文档

## Phase 1: 消除 DFA 输入重排 (Phase 1) - **已完成**

### 目标
消除 TensorRT 引擎中 DFA 插件前昂贵的 `Reformatting CopyNode` 和 `Transpose` 操作。在 Orin AGX 上，这些操作每层耗时约 3.15ms，总计约 18.9ms。

### 尝试 1: 调整 Permute 顺序 (V2)
- **方法**: 在 `export_head_onnxv3.py` 中，调整 `points_2d` 的 `permute` 顺序，使其在 Python 端输出 `[bs, num_anchor, num_pts, num_cams, 2]`。
- **结果**: 失败。TensorRT 依然插入了 `Reformatting CopyNode`，耗时未减少。

### 尝试 2: 广播 MatMul (V3)
- **方法**: 利用 MatMul 的广播特性 (`[B, 1, 1, C, 4, 4] @ [B, N, P, 1, 4, 1]`) 直接生成目标布局。
- **结果**: 失败 (性能退化)。虽然消除了 Reformat，但 TensorRT 在 Orin 上无法优化这种高维广播 MatMul，导致单层耗时从 ~2ms 暴涨至 **87ms**。

### 尝试 3: 显式循环 MatMul (V3.1) - **成功**
- **方法**: 
  - 在导出脚本中，将高维广播改为显式的 Python 循环。
  - 对 6 个相机分别执行标准的矩阵乘法 (`[B, N*P, 4] @ [B, 4, 4]`)，然后 Stack 结果。
  - 强制将 `points_2d` 和 `weights` 转换为 `FP32` 以匹配插件要求。
- **结果 (Orin AGX)**:
  - 总耗时从 **67.48 ms** (V2) 降低至 **49.35 ms** (V3.1)。
  - DFA 插件前的 `Reformatting CopyNode` 耗时几乎忽略不计。
  - 成功消除了约 **18 ms** 的开销。

## Phase 2: INT8 量化 (进行中)

### 现状 (基于 V3.1)
当前主要瓶颈：
1.  **FFN MatMul**: 12.8 ms (26%)
2.  **Softmax**: 10.1 ms (20%)

### 尝试 1: 全量 INT8 PTQ (Post-Training Quantization)
- **方法**: 
  - 使用 384 帧真实数据生成校准集 (FP32 ONNX)。
  - 解决 Calibrator 段错误问题 (使用 FP32 模型进行校准)。
  - 使用 `IInt8EntropyCalibrator2`。

#### 结果 A: RTX A6000 (开发环境) - **成功**
- **Latency**: Head1 端到端耗时 **9.64 ms** (Python测试)，纯 Kernel 耗时 **9.01 ms**。相比 FP16 Kernel 耗时 (10.37 ms) 提升约 **13%**。
- **分析**: 
  - FFN 层被正确量化。
  - 虽然提升幅度没有达到理论最大值 (通常 2x)，但足以抵消 Python 开销。
  - **异常**: 小 Batch/小维度的层在 INT8 下反而变慢 (量化开销 > 计算收益)，这可能是提升受限的原因。
- **可视化**: 结合 Top-K 过滤后，可视化结果与 PyTorch 高度一致。

#### 结果 B: Orin AGX (目标环境) - **失败 (性能回退)**
- **Latency**: Head1 耗时 **50.32 ms** (FP16 为 49.35 ms)，不降反升。
- **原因分析**: 
  - TensorRT 在 Orin 上将 `Shuffle` + `MatMul` 融合为 `{ForeignNode}`。
  - `ForeignNode` 无法利用 INT8 Tensor Core，且引入了额外的 Reformat/Copy 开销。
  - 导致 FFN MatMul 单层耗时从 2.14ms (FP16) 增加到 3.43ms (INT8)。

### 下一步修复计划: 针对 Orin 的强制量化
- **策略**: 
  1.  **强制精度 (Explicit Precision)**: 修改构建脚本，显式遍历网络层，强制将 FFN 的 MatMul 层精度设置为 INT8，禁止 TensorRT 回退到 ForeignNode。
  2.  **图结构简化**: 如果强制精度无效，尝试修改 ONNX 导出逻辑，移除 MatMul 前复杂的 Shuffle 操作。

### 并行任务: Backbone INT8 量化
- **目标**: 将 Backbone (ResNet-50 + FPN) 量化为 INT8。
- **预期**: Backbone 结构相对标准 (Conv + ReLU)，对 INT8 量化更友好，预期能获得稳定的加速且精度损失可控。
- **工具**: 已更新 `generate_calibration_data.py` 和 `build_engine.py` 以支持 Backbone。
